3Qué quedó construido, por capa

Núcleo de valuación (F1)

  • Tasación express anclada: port a Python del motor de market-anchors (mediana/p25/p75 USD/m² con re-ranking por similitud; mismos pesos 0.45/0.20/0.20/0.15 y umbrales del original validado). Fallback zona→provincia→nacional que informa el scope. Endpoint POST /api/valuations/express con ajuste LLM anclado + fallback determinístico si la IA falla. PDF brandeado + pantalla de 10 campos.
  • Smoke ejecutable: el motor ACM y el anchor son matemática pura → verificables sin DB. Romper un coeficiente lo detecta (exit ≠ 0). Es la vara antes de cada push de núcleo.

CRM + bot: la promesa del producto (F2)

  • DMO (Daily Method of Operation) multi-tenant: coaches + templates + bloques + asignaciones + logs, con las 5 metodologías oficiales como catálogo global clonable por workspace.
  • Pipeline legal AR: kanban de deals de 6 etapas con drag-and-drop, visitas con calendario, autorizaciones. Ranking del equipo pasó de N+1 (3 queries por vendedor) a 4 queries agregadas constantes.
  • Bot WhatsApp embebido: motor Gemini function-calling con 7 tools nativas scoped al workspace (buscar/consultar propiedades, agendar visita, registrar lead, tasación express por chat, derivar a humano con round-robin, cerrar). Config por workspace (no singleton). 18 tests de aislamiento/idempotencia/round-robin.
  • Inbox humano: tomar mando pausa el bot; producer único de eventos reales de Bandeja (lead, visita, derivación, firma, comentario).

Robustez (F3)

  • Audio full-duplex con degradación a texto si el proveedor falla.
  • Canal Meta Cloud API oficial por workspace con verificación HMAC fail-closed, unificado con Baileys en un solo módulo de salida (wa_out) y un solo pipeline entrante (wa_inbound) — la lección negativa de SalesBot (fan-out duplicado) se evita desde el día uno.
  • Push PWA + cron de resumen semanal con guard X-Cron-Key.
  • Scraping con Chromium en la imagen + refresh incremental del dataset.
  • Gate de calidad: ESLint 9 + react-hooks (regla dura 16), pytest, y CI Action que corre tsc + eslint + pytest sin deployar.

Producto / UX (F4) y Growth (F5)

  • Shell reorganizado en 5 módulos (Captar · Cartera · Equipo · Chat · Mercado) con visibilidad por rol y auto-update PWA.
  • Equipo real: invitaciones por token opaco (workspace+rol salen de la fila, no del cliente) + require_role aplicado a endpoints sensibles (antes definido y sin uso).
  • KSP productor v1.2 para que SalesBot/Media Studio consuman el knowledge base en vivo.
  • Landing nueva y onboarding self-service con generador de datos demo etiquetados y purga FK-safe que respeta lo real.

5Seguridad y performance corregidas

Seguridad
  • Fugas multi-tenant cerradas (settings IA, heatmap, IDOR en collaboration) — Fase 0, revalidadas por el smoke.
  • Tools del bot y KB scoped por workspace (2 workspaces no se cruzan).
  • require_role aplicado a settings, borrados, config del bot y gestión de equipo.
  • Meta webhook HMAC fail-closed (sin secret → 403).
  • Invitaciones por token opaco revocable/single-use; workspace+rol nunca vienen del cliente.
Performance
  • Detalle de estudio: 9 → 4 queries (selectinload anidado).
  • Dashboard de mercado: 15 → 4 queries (GROUP BY).
  • Ranking del equipo: N+1 → 4 queries constantes.
  • Inbox y conversaciones: list sin N+1 (1 query medido).
  • Cascade delete-orphan en MarketStudy (antes IntegrityError al borrar).
  • Cloudinary upload movido a to_thread (no bloquea el event loop).

7Pendientes para Infra acción requerida

7.1 — Migraciones (bloqueante del deploy). La Aiven compartida no tiene alembic_version ni las tablas/columnas del rework. Secuencia:
  • Base con schema viejo: alembic stamp 1e616292cc4e (baseline) y luego alembic upgrade head.
  • Base vacía: alembic upgrade head directo.
  • No usar solo stamp head — saltearía todas las columnas nuevas (fue lo pactado para Fase 0, ya no aplica: hay 12 migraciones posteriores al baseline).
  • Head final del rework: f7a8b9c0d1e2 (14 revisiones encadenadas, head único).
  • Aviso: un ALTER manual de monthly_reports.source se aplicó sobre la DB dev — la verdad canónica es la cadena Alembic del repo; en QA/prod correr desde baseline limpio.
7.2 — Variables de entorno / secrets a setear (ninguna está en código; todas por env / Secret Manager):
  • Bot: GEMINI_API_KEY; WhatsApp gateway: WA_GATEWAY_URL/WA_GATEWAY_KEY.
  • Audio: GROQ_API_KEY, ELEVENLABS_API_KEY, ELEVENLABS_DEFAULT_VOICE_ID.
  • Meta: META_ACCESS_TOKEN, META_WEBHOOK_VERIFY_TOKEN, META_APP_SECRET (globales, Tech Provider).
  • Push/cron: VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT, CRON_KEY + scheduler externo del resumen semanal.
  • KSP: KB_CLAVE_SALESBOT, KB_CLAVE_MEDIASTUDIO.
7.3 — Infra / build. Dependencia nueva pywebpush ⇒ cryptography subió 41→46 (verificado compatible con JWT/bcrypt): reconstruir imagen. Dockerfile ahora instala Chromium (~1.0-1.2GB estimado, confirmar con build real y dimensionar memoria de Cloud Run). CI Action ci.yml corre tsc+eslint+pytest en push (no deploya). El wa-gateway va con --min-instances=1 --no-cpu-throttling (websocket persistente).
7.4 — Cloudinary. El account tiene "Restricted media types" activo → bloquea la entrega pública de PDFs con 401. Mitigado sirviendo los PDFs por streaming desde el backend; para servirlos directo de Cloudinary, habilitar el toggle en Console → Settings → Security.

8Decisiones abiertas para el dueño

  • Íconos de la PWA: falta manifest.json para que la suite sea instalable como app — requiere íconos 192/512 de marca (proveerlos y armo el manifest).
  • Navegación del vendedor: hoy no ve Cartera ni Mercado (según el WO literal). Puede ser fuerte para un vendedor que carga propiedades — decir si se afloja.
  • Autorizaciones: el vendedor crea/edita las que captó; solo el borrado quedó gateado a admin/supervisor. Confirmar si querés gatear también create/edit.
  • Dataset de mercado: ~500 filas del seed son sintéticas y se mezclan con el dataset real de Coldwell (distinguibles por source). Decidir si se separan/etiquetan visualmente.
  • Landing: usa Tailwind CDN (sin build) → punto flojo de Lighthouse; verificar el buzón hola@tasar.app del CTA.
  • Página Ranking figura en el módulo Equipo pero no existe como ruta — falta crearla si se quiere.
  • Dataset CB --apply: sigue en dry-run (5013 de 9240 filas importables). Correrlo cuando quieras poblar market_listings (hace backup previo).
